影栈 0.6.10：设置持久化与文件视频接线

根因：parseTimeline 重建 output 时漏掉原 output 的扩展字段，导致导入/重新载入丢失 rollingGeneration、lowMemoryMode、memoryDiagnostics、rollingBaseManifest。改为先保留字段再规范原有字段。executionMode 本身没有在该处被删除；回归验证其导入/保存/提交一致性，不能把历史任务 legacy 值一律归因于此 bug。

普通生成仍输出 IMAGE/AUDIO，文件 first_pass_video/final_video 需要滚动生成。
前端：检查并运行及主运行按钮都会检查有效提交图；冲突时停止队列，提供开启滚动按钮（不自动生成）。设置与提交不一致时明确提示重新载入。重新载入请先保存工作流，并检查本轮摘要、仅二采按钮与滚动开关。
后端：隐藏 PROMPT 读取真实端口接线，进入导演台执行后、prepare_director_plan/采样/缓存写入前检查。可阻止绕过前端的 API 任务静默完成，但并非服务器全图排队前校验，上游节点可能已经执行。旧 IMAGE/AUDIO 接线不受影响。
已有正常一采缓存：保持节点 ID、cache_name、seed、参考与采样参数，选仅二采＋滚动生成＋全部导出。任何缓存不匹配仍停止，绝不自动重跑一采。
仅一采时最终 VIDEO 阻断仍是正常行为；不改为伪最终视频。滚动视频未就绪/宿主缺少接口的既有提示继续保留。
改动不涉及缓存格式、指纹、清理、采样、音轨或段间约束。无 GPU 实测，不以 CPU 和前端通过代替服务内存验收。
