# 分段固定一采 seed 与仅二采

CineStack H3 0.1.0，2026-10-13。基于上游提交 `8151b291fcacee5ddb70c6493eaed4f831bc6867`，未发布到上游。

每段可以固定自己的 `first_pass_seed`。Refine 新增 `refine_only`，开启后读取各段匹配的一采 AV latent，只运行二采；缓存缺失、失配或损坏时停止并列出具体段和原因。

## 使用步骤

1. 在每张素材组/首尾帧组卡片或源视频分段面板的“一采 seed”填写整数。空白继承导演台全局 seed；填写 `0` 表示固定为 0。不满意哪一段，就只修改那一段的 seed 并选择运行该段。
2. 制作一采时关闭 `refine_only`。需要先看一采结果时，接 Refine 并开启 `confirm_first_pass`，保持原有先确认一采流程。已固定分段 seed 的普通一采也会保存一采 latent，供以后精修使用。
3. 全部一采满意后，选中需要精修的段，接好二采 SIGMAS，将 Refine 的 `refine_only` 开启。无需为了混合 seed 分成多批。
4. 二采 seed 的 `inherit` 继承本段一采 seed；`offset` 为本段一采 seed 加偏移；`independent` 继续使用 Refine 自己的种子。

例如第1/2/4/5段固定为100，第3段固定为200，各段对应一采缓存均匹配后，全选仅二采会读取100/100/200/100/100的缓存。此时改变全局默认 seed 不会改变这些已固定的分段 seed。

## 仅二采如何停止

`refine_only` 不依赖 `confirm_first_pass` 开关。它优先于普通执行方式，只支持 `mode=refine` 或 `mode=upscale`。`latent_upscale` 本身不进行二采，启用仅二采时会拒绝执行。选中 fl2v 而 `skip_fl2v=true` 时同样提示该段被跳过，需要明确调整设置。

执行前先检查所有选中段的一采指纹，再逐个读取并校验一采 AV 文件。发现问题时不会开始任何一采或二采，也不会先清理分段缓存。示例错误：

```text
仅二采已停止，未执行任何一采或二采：
第 2 段：一采缓存失配：一采 seed（缓存=100，当前=42）
第 5 段：一采缓存失配：提示词
```

缺少 `.pre.meta.json` / `.pre.av.pt`、JSON 损坏、AV latent 无法读取等也会列出具体段。运行过程中若缓存文件被其他进程改变，读取该段时再次严格检查；仍不会回退一采。若前面的二采已执行，运行期间出现的文件变化不提供整批回滚。

只有选中的段参与预检。未选中的段继续使用原有全部导出的缓存/源片填充规则；要得到完整五段精修成片，应全选五段并确认每段均完成二采。

## 界面与素材组接线

普通素材组、首尾帧组、源视频分段面板均有“一采 seed”输入。值立即写入时间轴，复制片段、重新打开工作流、首尾帧重建和导演包往返都会保留。

外部 Group 的旧版节点和 Autogrow API 均新增可选字符串字段 `first_pass_seed`。外部 Group 的非空值优先；留空时使用导演台对应卡片的分段 seed，再留空才继承全局。直接编辑导演台卡片会同步回支持该字段的 Group 控件；如果该字段已接上游输入，卡片为只读，应在上游修改。

分段 seed 用十进制字符串保存到前端 JSON，后端转为整数，支持完整 uint64 范围 `0…18446744073709551615`。状态面板同时显示每段期望 seed、缓存 seed 和差异项，大整数通过文本字段显示，避免 JavaScript 舍入。

状态面板做快速元数据比较；真正运行前还会校验磁盘 latent。预检逐段释放读取的数据，不把整批大 latent 同时留在内存中；完整校验会增加一次缓存读取开销。

## 旧工作流与旧缓存

- 缺少 `first_pass_seed` 的旧段继续继承全局 seed；不自动改成固定种子。
- `refine_only` 默认关闭，并追加在 Refine 旧控件之后，避免旧 `widgets_values` 按位置恢复时错位。
- 仅二采关闭时，普通一采与“先确认一采”的原有执行方式保留。
- 一采指纹仍保存实际 `seed`，不增加“继承/固定”类型字段。把一段从继承A改为固定A，其他条件相同，可以继续使用原来的A缓存。
- 新增空白 Group seed 控件不会改变旧外部组接线指纹。显式 Group seed 另按每段实际值比较。
- 已有五段分别以A/A/B/A/A生成时，把对应分段字段填写为A/A/B/A/A，核对其余参数后即可尝试仅二采，无需为升级先删除缓存。

一采缓存检查仍以插件已有指纹体系为基础，检查 seed、提示词、素材记录、画布、时长、步数、CFG、采样器、调度器、SIGMAS、shift及可选模块设置等；本次未新增整个 MODEL/CLIP/VAE 的权重内容哈希。同名素材被覆盖或图外模型/LoRA变化时，不能仅凭缓存面板证明输入内容完全一致。

如果后段一采原本承接旧前段的尾部，重做前段后，固定后段 seed 会保留该后段已生成的旧上下文，不会自动修复接缝。需要改变后段一采时，关闭仅二采并明确选择该段重做。
