结论
本轮重跑完整 CPU/浏览器回归，并复查滚动生成、旧低内存/普通输出、缓存预检、
逐段 seed、连续性与中断资源路径。发现并修复 3 处可复现问题，新增 7 项回归。
不包含分线管理；不改变节点 ID、位置型控件、旧工作流默认行为或发布触发条件。
CPU/宿主适配测试不能替代真实 ComfyUI/GPU 验收；没有执行 Registry 发布。

一、修复及复现证据

1. P1：滚动导出重新加载的分段参考 PCM 逐段残留。
   路径：_run_one_segment 的 finally 释放 ref.audio；延迟 flush 调用原声音频
   准备函数时又加载 ref.audio 和 plan.audio_decode_cache，之后原先没有再次释放。
   使用 6 个真实 WAV 文件进行导出；修复前各段开始时残留参考音频数为
   [0, 0, 1, 2, 3, 4]，修复后为 [0, 0, 0, 0, 0, 0]。
   修复：在滚动 flush 的 finally 释放该段可从文件恢复的私有参考音频。
   成功和 KeyboardInterrupt 路径均验证；公共共享音频仍保留，输出 MP4 含音轨。
   此计数证明引用生命周期修复，不是 GPU 实测或操作系统 RSS 数值。

2. P2：严格仅二采预检没有校验 handoff 帧字段的类型/取值。
   缓存 JSON 语法有效，但第二段 trim_frames='broken' 时，原先在执行到第二段
   才报 int 转换错误，前段可能已采样；负数、布尔值和小数还可能被接受。
   修复：严格缓存读取阶段校验 trim_frames/export_frames/sample_frames/
   phase_align_trim 为非负整数。错误含段号、字段和数值，在采样与缓存清理前拒绝。
   未携带这些字段的旧缓存继续兼容；不自动补跑一采。

3. P2：WAV 收尾异常会跳过编码日志句柄关闭。
   模拟 WAV.close 抛出 OSError('disk full')，原先日志文件仍打开。
   修复：在独立 finally 中清空 WAV 引用并关闭日志；编码进程已退出且异常继续上抛。

二、复测范围

- 20 段一采：只有一个持续编码器；没有整片 RGB concat/逐段 MP4/完整 RGB 缓存；
  成功段的一采和最终 AV 各保存一次，进入下一段时仅上一段解码画面仍被引用。
- 新增 20 段二采：第一/最终阶段分开输出，各 100 帧；下一段 conditioning 时
  至多保留上一段的两个阶段解码张量，运行结束后弱引用全部失效。
- 连贯：22 帧引导、phase 裁剪、接缝/调色与旧拼接像素对照、仅二采复用裁剪长度。
- 缓存：独立 seed、0/uint64 上限、继承、失配原因、损坏/消失、LoRA/SIGMAS、
  严格拒绝和普通模式既有行为；部分运行只恢复需要的上一段 AV。
- 选段：连续/不连续选段，仅输出选中段，manifest 帧区间及顺序对应实际视频。
- 输出：确认暂停、多个精修轮次、混合确认阶段 *.partial、不同画布合并、
  缺失音轨/重采样、30000/1001 帧率累计取整、奇数画布偶数填充。
- 失败：编码失败、解码 OOM、用户中断、WAV 收尾失败；进程/句柄清理及缓存保留。
- 浏览器：迁移、总览/卡片同步、精确 seed、异步预检取消、queuePrompt false、
  Refine/Reroute/旁路、FL2V、外接组、低内存/滚动开关互斥及序列化、中英文、销毁。
- 交付：版本/依赖/节点映射、9 个示例工作流、Python 3.10 语法、JS 语法、
  Apache-2.0/NOTICE 保留、git diff --check、Registry 仍只由手动工作流触发。

四、仍需目标设备验证的边界

- 完整节点加载、真实 H3 一/二/N采、脸修、模型卸载、画质/音视频同步、RSS/VRAM
  峰值和耗时未在用户 GPU 上执行。不能据此承诺所有 OOM 已解决或固定提速比例。
- 当前段＋上一段约束的是生成段工作数据。模型、共享参考、原始输入素材与源视频
  音频缓存仍有独立占用；本修复针对延迟导出再次加载的分段文件参考 PCM。
  源视频编辑模式仍可能缓存完整源音频，不应把该模式称为所有输入内存恒定。
- 缓存没有完整 MODEL/CLIP/VAE 内容哈希；更改上游模型或覆盖同名素材仍需显式
  管理缓存。前段变化不会自动重做已保存的后段，旧后段仍含生成当时的上下文。
- 硬杀进程/系统 OOM 无法保证末尾视频/WAV 封装；不提供正在编码 MP4 的无损续接。
- 已有正常工作流不自动开启滚动。更新后重启 ComfyUI；GPU 压测仍需用户设备验收。
