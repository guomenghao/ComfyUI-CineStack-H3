影栈 CineStack H3 0.3.0：低内存落盘模式
2026-10-14

开启位置
导演台的输出设置区，勾选“低内存落盘”。旧工作流缺少此字段时默认关闭；不增加位置型节点控件、不改变节点 ID。
设置保存为 timeline_data.output.lowMemoryMode=true，导演包、FL2V 及外接 Group 路径均保留它。

执行与交付
开启后，原“全部/分段导出”选择暂时禁用；只交付本轮实际运行的勾选段，不把未勾选旧段全部读回 RAM 填充。
“仅一采”“仅二采”“按原接线”仍独立生效；要交付整条时间轴，请全选要交付的段。
完整视频直接写到 ComfyUI/output/minimax_seg_export/时间戳目录，具体绝对路径显示在 Director report 中。

- seg_XXXX.mp4：该段正常/最终画面；仅一采模式下也是这一命名。
- seg_XXXX_pre.mp4：确认一采停留段，或二采前的一采对比画面。
- seg_XXXX_pN.mp4：各轮精修视频。
- seg_XXXX_facepre.mp4：启用“输出修脸前”时的文件。
- first_pass.mp4：本轮全部选中段都具有一采视频时，自动从磁盘合并的一采。
- final.mp4：本轮全部选中段都具有最终视频时，自动从磁盘合并的成片。
- manifest.json：片段序号、实际一采 seed（精确十进制字符串）、文件、帧数、分辨率和运行状态。

确认一采与已有缓存二采混跑时，缺少某阶段的段不会被伪装成另一阶段混合输出；报告会说明为何没有该阶段合并视频。
不要删除分段文件后再只依赖尚未生成的合并文件；manifest 状态 completed 才表示本轮完整完成。
失败或中断时已写完的分段和一采缓存保留，running 表示尚未完成，不会自动补跑一采。

IMAGE/AUDIO 接口
低内存模式会用 ComfyUI ExecutionBlocker 阻断 images、images_pre_refine、source_images、images_pre_face_refine 和 audio。
下游 Preview/CreateVideo/SaveVideo 不会收到完整片段；请直接使用落盘视频。
fps、frame_count 和 report 仍输出。关闭开关后恢复旧 IMAGE/AUDIO 工作流。
勾选“输出修脸前”仍可保存对应文件；“输出原片”的 IMAGE 对比在此模式不输出。

每段释放时机
1. 一采成功后，先原子保存 AV latent 和交接元数据，再解码/编码；解码失败也可保住这次一采 latent。
2. 一采确认阶段只做一次 VAE 解码，不为两个输出口重复生成同一画面。
3. 当前段视频与缓存成功落盘后，仍保留上一段必要的完整画面、AV、音频与交接记录，供下一段钉帧、分级和 phase-align 尾帧修剪。
4. 下一段使用完毕后释放更早的完整画面；保留的 IMAGE 占位仅 2×2，旧段音频及中间精修 RGB 不继续累计。
5. 原拼接的接缝处理逐对执行并更新前段文件；不会创建整条时间轴的 Python 图像张量。
6. 模型卸载后清掉本段 SigmaShift 克隆引用，避免分段 LoRA 的 patcher 在整次执行中一直积累。
7. 完成后释放最后的工作集，从磁盘流式合并。MP4 逐帧转 RGB，不创建全段 .tobytes() 副本；缓存转 uint8 也逐帧转换。

合并说明
合并是对已导出视频的流式 H.264 编码，不是原始浮点 IMAGE 的无损导出。需要时逐文件补画布和静音轨，保留完整帧数。
FFmpeg 使用有限编码线程；不把全部段解码回 Python 内存。
段间 guide/continue、22 帧上下文、上一段 AV 选择、尾帧修剪、独立 seed 和严格仅二采校验保持原路径。
低内存选段运行仍可从上一段磁盘缓存承接连贯；缺失的上下文按原连贯规则提示，绝不为补齐输出自动采样未勾选段。

缓存与错误
低内存开关不参与一采生成指纹，所以单纯切换开关不会让原有匹配缓存失效。
新一采没有同时写 RGB 缓存时，会清理同槽旧 RGB 预览，防止新 seed latent 搭配旧 seed 画面；之后需要时从新 latent 解码。
缓存或视频写盘失败会明确抛错并停止；不会继续丢弃未保存的画面，不会回退为整片 RAM 输出。
FFmpeg 不可用时在采样/缓存清理前停止；已有 imageio-ffmpeg 或系统 FFmpeg 均可，无新增运行依赖。

日志
每段保存后会打印 CineStack RAM: segment ... RSS=... MiB。
RSS 是当前 Python 进程驻留内存，不是 GPU 显存；Linux 文件页缓存、FFmpeg 子进程、模型常驻内存和分配器保留空间另计。
释放张量引用意味着后续可复用/回收，不保证 top 中 RSS 每段立刻回到初始值。
此模式消除随已完成完整画面数量持续累积的路径；当前段和上一段、VAE/模型、长参考视频等仍需要内存。
单段过大或容器内存上限不足仍可能 OOM；本功能不承诺任意长度、分辨率都能运行。

验证
低内存专项覆盖真实 FFmpeg 编码/合并、不同画布/缺音轨、帧数、12 段弱引用与输出存储上界、重复解码消除、
22 帧连贯取用及 phase trim 重写、旧拼接与流式交付画面像素对照（容许 H.264 量化误差）、写盘/解码失败、
精确 uint64 seed、低内存一采缓存接严格二采、失配整批拒绝、选段、外接组与导演包、媒体输出阻断。
GPU 采样/官方钉帧适配使用测试桩；真实模型的画质、音视频同步和用户服务器 RSS/容器峰值仍需实机确认。
